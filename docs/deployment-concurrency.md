# 并发修复的验证与上线前置条件

本次代码包含账务/审核事务保护、报名与周期额度约束、会员身份竞争恢复，以及会员和管理页面修复。超级管理台分成「管理员名单」和「规则配置」两个独立页面，各自加载和保存。

## 本地验证

使用 Node.js 24，按两个 package-lock.json 安装依赖后执行：

```sh
npm test
npm run typecheck
node --check cloudfunctions/api/index.js
```

后端回归通过实际 `exports.main` 调用隔离内存数据库。适配器实现文档唯一约束、事务快照、文档版本冲突重试和回滚，`count()` 按实际 SDK 行为查询事务外已提交数据。页面回归运行真实 TypeScript 页面方法及 API 模块，覆盖请求合并、错误码、分页、额度补填、余额同步、时间校验和拆分页面保存。

这些检查不代替真实微信开发者工具、云数据库事务和索引验证。测试不连接真实会员数据。

## 上线前先核查身份数据与索引

1. 确认操作的是正确的微信云开发环境，保留可恢复的数据备份。当前云工作区没有用于访问目标微信云数据库的身份，线上索引和历史数据尚未核验。
2. 暂停会员/管理员业务写入及外部脚本，停止旧版本写入者。核查 `members.openid` 与 `members.accountName` 数据及索引。
3. 在目标环境控制台确认这两个字段分别有唯一索引；不能只看文档里写着“唯一”。账号名按现有代码的小写规范存储。核查缺失、非法和大小写冲突数据后再创建缺失的索引，不对未核查数据直接执行清理或批量改名。
4. 可在**具备目标环境 SDK 身份且已设置正确环境**的执行上下文运行只读脚本：

   ```sh
   node scripts/check-member-identities.cjs
   ```

   脚本沿用 `wx-server-sdk` 的 `DYNAMIC_CURRENT_ENV`，不会选择或登录其他身份。云函数本身的身份不等于本机 shell 的身份；不具备该身份时应在受支持的目标环境中运行，不能把本地失败当作线上数据结论。脚本只输出数量，不输出 openid、账号名或凭据，不执行写入；出现重复或非法数据时退出失败。它不读取控制面索引列表，数据检查通过后仍须人工核对索引。扫描期间必须保持停写，避免分页移动。
5. 如果发现重复会员，先核对积分、明细、报名等关联，形成单独合并方案确认后处理。不得简单删重复会员、重写所有 memberId 或自动改名。本次代码保留已有随机会员 ID，创建唯一键冲突后回读竞争胜者；不引入新的身份映射表。

缺少唯一索引时，同进程请求合并无法保护跨实例首登，账号名跨会员竞争也无法完全保证。上述索引是已选方案的必要前提，不可仅凭本地模拟测试宣称已在生产生效。

## 整体切换后端写入者

- 新增 `operation_guards` 集合，沿用首次调用自动建集合机制。集合只允许服务端访问，不能向小程序客户端开放写入。
- 消费额度、评论审核和赛事报名的所有新版本写入口共同读写固定约束文档，用事务冲突重试串行约束资格。报名、取消、管理员补录/移除都必须一起更新。不要把单个新入口与旧入口混跑。
- 当前 SDK 的 `count()` 请求不携带事务标识。代码在事务读取/写入共同约束文档后，每次重数已提交历史记录；共同文档的冲突使竞争请求重试并重新计数。此保证依赖全部相关写入者遵守相同约束，控制台直接改业务记录或旧云函数会破坏此前提。
- 所有业务事务经过统一适配层，兼容当前微信 SDK 在文档操作阶段包装冲突时丢失原始 `code` 的行为。仅对明确冲突码或受限定的规范冲突文本重试整个事务，最多四次尝试；关闭 SDK 内层重试以避免预算叠加。普通系统错误、网络超时、权限失败和业务拒绝不会被当成冲突重放。真实 SDK 的本地发送器测试覆盖操作阶段及提交阶段，不等于已完成真实云端并发验证。
- 历史有效报名与已有消费/审核记录参与计数，不做从零开始的计数迁移。更改周期规则后仍按历史记录重新核对。遇到历史重复有效报名会明确要求核查，不自动合并。
- 云函数、前端接口和新页面应配套发布。审核接口现在返回 `items/total/page/pageSize`，接收 `processed` 及分页参数；余额响应新增等级字段。发布过程中保持停写，待旧执行实例排空后启用新写入口。

## 在隔离云测试环境验证后再恢复业务

使用专用测试会员，验证首次初始化竞争、余额为 10 时并发各扣 8、同申请并发通过/拒绝、最后一个普通额度竞争、最后名额竞争、取消/重报、管理员超额补录，以及审计写入失败时回滚。确认 SDK 的缺失文档/重复键/事务冲突错误可被准确识别。

在微信开发者工具验证新页面路由、两页各自保存、返回时未保存提示、审核分页、报名不可用状态、额度补填及日期校验。完成后恢复业务写入。当前变更没有执行生产部署、建索引或历史数据迁移。
